USTEC M1 Demo — Help

Candlestick chart of USTEC (Nasdaq 100) minute data with replay, Sonic R tooling and a programmatic range-query API. ← back to the chart

Chart & timeframes

  • Candlesticks rendered with Lightweight Charts.
  • Timeframe selector: 1m 5m 15m 30m 1H 1D. Higher timeframes are resampled from the 1-minute source; buckets with no underlying candle are skipped.

Navigation

  • Mouse wheel: zoom the time axis. Drag: scroll the chart.
  • Hold Space + left-drag: pan the visible window (chart cursor changes; other tools stand down while panning).

Bar replay

  • Enter Replay truncates the chart at the replay cursor and shows a trailing window (~1200 bars).
  • Controls: Play/Pause, Step, speed (1x–10x), position slider, and jump-to-time (DD/MM/YYYY HH:MM, UTC).
  • Everything is WYSIWYG in replay: indicators, session boxes and exports/API see only bars up to the cursor — the replayed future never leaks.

Indicators & overlays

  • Sonic R — EMA structure with wave/leg patterns and entries; toggle Show waves/legs for details.
  • Order blocks — LuxAlgo-style bullish/bearish order blocks.
  • NY Macro Times — macro-time boxes for New York sessions.
  • Asia / London / New York session boxes are drawn automatically.

Select Range tool

  1. Click Select Range — the cursor becomes a crosshair.
  2. Press and drag left→right (either direction works); both edges snap to the nearest bar.
  3. On release a popup offers Export CSV (auto-named download), Copy Markdown (table to clipboard) and Clear.

Escape cancels an in-flight drag or clears the selection (the tool stays armed). The selection persists across timeframe switches — edges re-snap to bars of the active timeframe, and exports always contain the active timeframe's bars. See DATA_EXPORT.md for the CSV/filename conventions.

Programmatic API — window.ustec

Query bars for a time range from the console or scripts. The API returns exactly what the Select Range tool would export for the same bounds (replay-aware, inclusive edges).

Methods

MethodReturnsDescription
queryRange(start, end, opts?) RangeQueryResult Bars with time in [start, end] (inclusive; swapped if reversed).
getSelection() RangeQueryResult | null Re-queries the current on-chart selection; null when none.
toCsv(result) string CSV identical to the Export CSV payload.
parseTime(input) number | null Parses a time argument to UTC seconds.
timeframes array Available timeframes as { label, seconds }.

Options (opts)

OptionTypeDefaultMeaning
timeframe label or seconds active chart timeframe '5m', '1H', 300, … (case-insensitive)
limit positive integer unlimited Max rows returned, taken from the start of the range. Invalid values throw.

Result shape

FieldMeaning
symbol, timeframe, intervalSecondsWhat was queried.
requestedNormalized bounds, UTC seconds (lo before hi).
from, toFirst/last returned bar, 'YYYY-MM-DD HH:MM:SS' UTC; reflect any limit truncation; null when empty.
barCount, barsRow count and the bars: { time, open, high, low, close, volume } (tick volume), ascending.
availableFull extent of the queried (effective) dataset, UTC seconds.

Time formats

  • UTC epoch seconds: 1756724400
  • CSV convention (UTC): '2025-09-01 09:30', '2025-09-01 09:30:45' (space or T separator)
  • Date-only (UTC midnight): '2025-09-01'
  • ISO 8601 with timezone: '2025-09-01T09:30:00Z', '2025-09-01T11:30:00+02:00'

Other ISO forms without a timezone are rejected — they would silently parse as local time. Unknown timeframes and invalid times throw with the accepted formats in the message.

Examples

// first 10 candles of September 2025 on the 1H timeframe
const r = window.ustec.queryRange('2025-09-01', '2025-10-01', { timeframe: '1H', limit: 10 });
r.barCount;  // 10
r.from;      // '2025-09-01 00:00:00' (UTC)
r.to;        // last returned bar — reflects the limit

// whole range, active timeframe, epoch seconds
window.ustec.queryRange(1756724400, 1756983600);

// whatever is currently selected on the chart
window.ustec.getSelection();

// same CSV the Export button downloads
console.log(window.ustec.toCsv(r));

From the terminal — HTTP API & CLI

The same query core runs outside the browser (from ustec-demo/). Server-side there is no replay cursor: queries always see the full dataset. Default timeframe when omitted is 5m. 

# HTTP endpoint (npm run serve-api, default port 5200; --port to change)
curl 'http://localhost:5200/api/range?start=2025-09-01&end=2025-09-02&limit=10'
curl 'http://localhost:5200/api/range?start=2025-09-01&end=2025-09-02&timeframe=1H&format=csv'

# CLI (json default; --format csv for pipeable rows)
npm run query -- --start '2025-09-01 09:30' --end '2025-09-05 16:00' --limit 10 --format csv

HTTP errors return 400 with { error }; unknown paths 404. CSV responses carry the UI's export filename in Content-Disposition.

Data & conventions

  • Source: MT5 tab-separated export USTEC_M1_202508010000_202603031408.csv (2025-08-01 → 2026-03-03, ~205k 1m candles).
  • All timestamps are UTC; volume is tick volume (TICKVOL), summed when resampled.
  • CSV header: time,open,high,low,close,tickvol; export filenames follow <SYMBOL>_<TIMEFRAME>_<START>_<END>.csv with compact UTC stamps.
